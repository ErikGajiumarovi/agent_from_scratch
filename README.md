# Примитивный ИИ-агент с нуля (Python + Ollama Cloud)

Самый маленький пример, чтобы **понять, как создаются агенты**. Без LangChain, без фреймворков — только `requests` + цикл.

Модель: `gemma4:31b` через Ollama Cloud (`https://ollama.com/api/chat`).

## 1. Запуск за 1 минуту

```bash
pip install -r requirements.txt
export OLLAMA_API_KEY="ваш_ключ_с_ollama.com/settings/keys"
python agent.py
```

> Где взять ключ: [ollama.com/settings/keys](https://ollama.com/settings/keys)

Проверочные вопросы (история помнит всё — задавайте по порядку!):
- `Сколько будет 137 * 46 + 11? Посчитай калькулятором.`
- `Запомни это число как моё любимое.`
- `Какое моё любимое число? Прибавь к нему 100 через калькулятор.`

Команды в чате:
- `/history` — показать всю историю (сообщения + tool calls)
- `/reset` — очистить историю
- пустая строка — выход

## 2. Как это устроено? (5 частей агента)

```
┌─────────────────────────────────────────┐
│  ПАМЯТЬ (messages)                      │  вся история: система + вопрос + шаги
│      │                                  │
│      ▼                                  │
│  ┌───────┐   JSON    ┌──────────────┐    │
│  │ МОЗГ  │ ────────► │ ИНСТРУМЕНТЫ  │    │
│  │ LLM   │           │ (Python)     │    │
│  └───────┘ ◄──────── └──────────────┘    │
│     ▲           наблюдение               │
│     │                                    │
│  СИСТЕМНЫЙ ПРОМТ (правила игры)          │
└─────────────────────────────────────────┘
         ЦИКЛ ReAct повторяется до ответа
```

1. **Мозг (LLM)** — `call_ollama()` шлёт POST на `https://ollama.com/api/chat` с моделью `gemma4:31b` + полем `tools`. Модель сама ничего не умеет, кроме генерации текста и `tool_calls`.
2. **Инструменты** — обычные Python-функции в `agent.py` + `TOOLS_SPEC` (JSON-схема для модели):
   - `tool_calculator(expression)` — считает через `ast` (безопасно, без `eval` всего подряд);
   - `tool_get_time()` — возвращает текущее время (LLM его не знает).
3. **История** — один список `history` на всю работу программы. Типы сообщений:
   - `system` — инструкция (1 раз в начале);
   - `user` — вопрос человека;
   - `assistant` (+ `tool_calls`) — ответ модели; вызов инструмента лежит в `tool_calls`, а не в тексте;
   - `tool` — результат Python-функции.
   
   Каждый запрос в API уходит **вся история целиком** — поэтому агент помнит прошлые вопросы. Посмотреть можно командой `/history`, сохраняется в `history.json`.
4. **Цикл ReAct** — `run_turn()`: *Вопрос → История в API → tool_calls → Выполняю Python → tool в историю → Повторяю* (макс. 5 шагов).
5. **Системный промт** — короткая инструкция на русском: когда вызывать `calculator` / `get_time`, не выдумывать результаты.

## 3. Как добавить свой инструмент? (3 шага)

Пример — погода-заглушка:

```python
def tool_weather(city: str) -> str:
    return f"В городе {city} сейчас +20°C, солнечно (демо-заглушка)."

# 1. Добавить функцию в TOOLS_IMPL:
TOOLS_IMPL["weather"] = tool_weather

# 2. Добавить описание в TOOLS_SPEC:
# {"type": "function", "function": {
#     "name": "weather",
#     "description": "Погода в городе",
#     "parameters": {"type": "object",
#         "properties": {"city": {"type": "string"}},
#         "required": ["city"]}}}

# 3. Добавить ветку в execute_tool():
#    if name == "weather":
#        return TOOLS_IMPL[name](args.get("city", ""))
```

## 4. Частые вопросы для новичков

**Почему агент, а не просто чат?**
Чат только генерирует текст и врёт в математике/времени. Агент может вызывать код, API, базы данных — и проверять результат. А история (`user` / `assistant` / `tool`) даёт ему память между вопросами.

**Что дальше учить?**
1. Стриминг ответов (`stream: true`);
2. Векторная память / RAG;
3. Фреймворки: LangChain, Haystack, SmolAgents.

## 5. Безопасность ключа

Важно: никогда не коммитьте реальный `OLLAMA_API_KEY` в git. Используйте переменную окружения или `.env` (см. `.env.example`). Если ключ уже засветился — пересоздайте его на сайте Ollama.
